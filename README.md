# 预约管理项目工作目录

整理日期：2026-07-31

## 一句话结论

当前项目可以自洽的主线是：以 `预约管理需求-汇总材料 - 260721.xlsx` 的 `需求` TAB 作为功能实现基线，以 `基础信息表.xlsx` 作为权限和数据范围参考，以 `预约/` 作为页面拆分和交互参考；旧 Axure 的 Web/移动端原型已放入归档，只作为历史交易流程参考，不作为当前范围基线。

## 目录说明

- `预约管理需求-汇总材料 - 260721.xlsx`
  - 当前需求汇总和排期，其中 `需求` TAB 是后续功能范围、规则和验收判断的最高优先级资料。
- `基础信息表.xlsx`
  - 当前角色权限矩阵，是权限边界和数据范围判断的最高优先级资料。
- `预约/`
  - 当前主原型参考。推荐入口是 `预约/index_预约管理.html`，用于辅助理解页面拆分和交互，不覆盖 `需求` TAB 的规则口径。
- `历史原型索引.md`
  - 旧 Axure Web/移动端原型的页面索引和取舍说明。这里只保留索引，不复制大量 Axure 运行时文件。
- `历史业务参考索引.md`
  - WMS 操作手册、Visio 流程图的参考定位。它们是业务背景，不是本次预约管理新需求的直接范围清单。
- `_archive/`
  - 已归档的旧资料、压缩包、旧 Axure 导出包和本次清理前的接管资料包。
- `docs/implementation-plan.md`
  - 当前实施计划，包含页面清单、组件清单、状态机、接口依赖和验收用例。
- `docs/implementation-audit.md`
  - 当前实现核查，说明哪些需求规则已实现、哪些仍是 mock 或待接后端。
- `app/`
  - 按实施计划落地的无外部依赖 MVP 前端，包含用户端 PC/移动适配和管理端 PC。
- `tests/`
  - 状态机和 mock API 冒烟测试。
- `UI-PC.png`、`UI-mobile.jpg`
  - 用户确认的视觉参考：浅灰背景、低饱和纯色卡片、清新易读、移动端卡片化。

## 实施工程入口

- 本地页面：`http://127.0.0.1:8091/`
- 静态入口：`app/index.html`
- 测试命令：`node tests/smoke-tests.mjs`

当前实现采用静态前端 + mock API。真实后端接入时，优先替换 `app/mock-api.js` 的接口边界，保留 `app/state-machines.js` 中的状态规则作为业务校验基线。

## 建议工作方式

1. 后续需求澄清、研发拆解、测试用例设计，以 `预约管理需求-汇总材料 - 260721.xlsx` 的 `需求` TAB 为最高优先级。
2. `预约/` 只作为页面和交互参考；如果原型与 `需求` TAB 冲突，按 `需求` TAB 修改实现。
3. 如果需要补齐表单字段、领料/到货交易流程，可参考旧 Axure 页面，但要先映射到当前需求模块。
4. 不建议在活跃工作目录里继续维护 Axure 播放器运行时、锁文件、Chrome 插件说明页等噪音文件。
5. `_archive/20260731_项目清理归档/` 保留作证据链；主目录是清洗后的工作视图。
